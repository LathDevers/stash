# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Stash is a self-hosted Go web app for organising a media collection. Single binary serves a GraphQL API + an embedded React UI; data lives in SQLite. Released under AGPL.

- Backend: Go (entry: [cmd/stash/main.go](cmd/stash/main.go)), GraphQL via gqlgen, SQLite via `jmoiron/sqlx` + `golang-migrate`.
- Frontend: React 17 + TypeScript + Vite + Apollo client, in [ui/v2.5/](ui/v2.5/). pnpm is the package manager; npm scripts are the entry points.
- Companion binary: `phasher` (perceptual hashing), entry at [cmd/phasher/](cmd/phasher/).

## Build & development

All workflows run through the top-level [Makefile](Makefile). On Windows use `mingw32-make`; on OpenBSD use `gmake`.

### First-time setup

1. `make pre-ui` — installs UI deps via `pnpm install --frozen-lockfile`. Required after clone or when UI deps change.
2. `make generate` — generates Go + TS GraphQL code, dataloaders, and login locales. Required before the first build and after any `graphql/schema/**.graphql` change.

### Daily dev loop (two terminals)

- `make server-start` — runs the backend from source against a `.local/` config (port 9999). Backend has **no hot-reload**: stop and re-run after Go changes.
- `make ui-start` — runs Vite dev server (port 3000) proxying to the backend. Browser hot-reloads on UI edits. Override the backend URL with `VITE_APP_PLATFORM_URL`, but auth cookies will not cross origins.
- `make server-clean` — wipes `.local/` to start fresh (re-runs setup wizard).

### Building binaries

- `make build` — debug build of `stash` + `phasher` (dynamic linking).
- `make build-release` — release build (`flags-release flags-pie build`, strips debug info).
- `make ui` — builds the production UI bundle into `ui/v2.5/build/` (embedded into the Go binary via `ui.go`).
- `make release` / `make` (default) — full pipeline: `pre-ui generate ui build-release`.
- `make stash-macapp` — packages a macOS `Stash.app`.
- Cross-compile targets (`build-cc-windows`, `build-cc-macos`, `build-cc-linux`, etc.) are meant to run **inside** the `ghcr.io/stashapp/compiler` Docker container; see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). `make start-compiler-container` / `make remove-compiler-container` manage it.

Build-tag conventions (set in Makefile via `GO_BUILD_TAGS`):
- Always added: `sqlite_stat4`, `sqlite_math_functions`.
- Static builds add: `sqlite_omit_load_extension`, `osusergo`, `netgo` (Linux/BSD only).
- `integration` is added by `make it` to enable integration tests.

### Tests

- `make test` — unit tests (`go test ./...`).
- `make it` — adds `-tags integration` and runs the full suite, including SQLite integration tests in [pkg/sqlite/](pkg/sqlite/). Use this before merging backend changes.
- `make generate-test-mocks` — regenerates mockery mocks for all `*ReaderWriter` interfaces in [pkg/models/](pkg/models/) into [pkg/models/mocks/](pkg/models/mocks/) (config in [.mockery.yml](.mockery.yml)).
- Run a single test: `go test -tags "sqlite_stat4 sqlite_math_functions" -run TestName ./pkg/path/...` (omit `-tags` only for packages that don't touch SQLite).

### Linting / formatting / PR validation

- `make lint` — runs `golangci-lint` per [.golangci.yml](.golangci.yml) (errcheck, errorlint, gocritic, govet, revive, staticcheck, etc.).
- `make fmt` — `gofmt -w` everything; `make fmt-ui` — Prettier over UI + GraphQL.
- `make validate-backend` — `lint` + `it`.
- `make validate-ui` — `pre-ui` + `generate` + `cd ui/v2.5 && npm run validate` (eslint + tsc check + Prettier check).
- `make validate` — everything required for a PR.
- Quick variants run on changed files only: `make fmt-ui-quick`, `make validate-ui-quick` (skip tsc). Useful before commit.

## Code generation — what is auto-generated

Several files are gitignored or generated; **never hand-edit them**, and re-run `make generate` after touching the source schema:

- [internal/api/generated_exec.go](internal/api/generated_exec.go), [internal/api/generated_models.go](internal/api/generated_models.go) — gqlgen output from [graphql/schema/](graphql/schema/) (config: [gqlgen.yml](gqlgen.yml)). Triggered by `//go:generate` in [cmd/stash/main.go](cmd/stash/main.go) → `make generate-backend`.
- [internal/api/loaders/*_gen.go](internal/api/loaders/) — dataloader scaffolding generated from [internal/api/loaders/dataloaders.go](internal/api/loaders/dataloaders.go). `make generate-dataloaders`.
- [ui/v2.5/src/core/generated-*.ts](ui/v2.5/src/core/) — Apollo TS hooks/types from the same GraphQL schema. `make generate-ui` (runs `npm run gqlgen`).
- [pkg/stashbox/graphql/generated_*.go](pkg/stashbox/graphql/) — stash-box GraphQL client (config: [.gqlgenc.yml](.gqlgenc.yml)). Regenerated via `make generate-stash-box-client`.
- [ui/login/locales/](ui/login/locales/) — generated by `make generate-login-locale`.
- Mocks under [pkg/models/mocks/](pkg/models/mocks/).

If you change a `.graphql` file, run `make generate` (which calls both `generate-backend` and `generate-ui`).

## Architecture overview

Top-level layout:

- [cmd/](cmd/) — binary entry points.
- [internal/](internal/) — packages private to this module. Most application wiring lives here.
- [pkg/](pkg/) — domain logic and persistence. Conventionally importable, though not a public API.
- [graphql/](graphql/) — schema definitions for the Stash API and the embedded stash-box client.
- [ui/](ui/) — `ui.go` embeds the built React app; `ui/v2.5/` is the React source.
- [pkg/sqlite/migrations/](pkg/sqlite/migrations/) — versioned schema migrations (`N_*.up.sql` / `.down.sql`, with occasional `N_postmigrate.go` for code-driven steps).

### Request flow

1. [cmd/stash/main.go](cmd/stash/main.go) wires `config.Initialize` → `manager.Initialize` → `api.Initialize`.
2. [internal/manager/](internal/manager/) owns the long-lived singleton: database handle, job queue, scrapers, plugin runtime, ffmpeg, scheduled tasks ([internal/manager/task/](internal/manager/task/)), and the running-streams registry. The `Manager` is the integration hub — most subsystems hang off it.
3. [internal/api/](internal/api/) hosts the HTTP server, the gqlgen resolvers (`resolver_*.go`), authentication, dataloaders, and websocket subscriptions. Resolvers are intentionally thin — they call into managers and `pkg/<domain>` services.
4. [pkg/models/](pkg/models/) defines domain types (`Scene`, `Performer`, `Tag`, `Group`, `Image`, `Gallery`, `File`, `Folder`, …) and per-entity `Reader` / `Writer` / `ReaderWriter` interfaces. **Repositories code against these interfaces**, which is what makes the mockery test mocks possible.
5. [pkg/sqlite/](pkg/sqlite/) implements those interfaces against SQLite, including filter/criterion translation in `criterion_handlers.go` and `filter.go`. Transactions are managed via [pkg/txn/](pkg/txn/).
6. Per-domain service packages — [pkg/scene/](pkg/scene/), [pkg/performer/](pkg/performer/), [pkg/group/](pkg/group/), [pkg/tag/](pkg/tag/), [pkg/studio/](pkg/studio/), [pkg/image/](pkg/image/), [pkg/gallery/](pkg/gallery/), [pkg/file/](pkg/file/) — hold business logic (create/update/import/export), keeping resolvers and SQLite repos clean.

### Cross-cutting subsystems

- [pkg/scraper/](pkg/scraper/) — multi-engine scraping (XPath/JSON/Lua-style scripts/stash/freeones/graphql). Drives "Identify" and the Tagger UI.
- [pkg/stashbox/](pkg/stashbox/) — client for stash-box (StashDB and community instances). Generated GraphQL client; never hand-edit `generated_*`.
- [pkg/plugin/](pkg/plugin/) — Go-routine + JS-runtime plugin host; plugins can register hooks (e.g. `Scene.Update.Post`), expose tasks, and add UI assets.
- [pkg/job/](pkg/job/) — job queue used by every long-running task surface (scan, generate, identify, autotag, export, clean).
- [internal/autotag/](internal/autotag/), [internal/identify/](internal/identify/) — orchestrate scraper output and tag matching for the matching task types.
- [internal/dlna/](internal/dlna/) — UPnP/DLNA server (optional surface).
- [internal/desktop/](internal/desktop/) — system-tray/desktop integration for the bundled apps.
- [pkg/ffmpeg/](pkg/ffmpeg/) — ffmpeg wrapper used for transcoding, sprite/thumbnail generation, and stream HLS/DASH endpoints.
- [pkg/javascript/](pkg/javascript/) — Goja runtime shared by JS scrapers and JS plugins.

### Frontend overview

- Entry: [ui/v2.5/src/index.tsx](ui/v2.5/src/index.tsx), router/layout in [ui/v2.5/src/App.tsx](ui/v2.5/src/App.tsx).
- [ui/v2.5/src/core/](ui/v2.5/src/core/) wraps Apollo (`createClient.ts`, `StashService.ts`) and re-exports generated GraphQL operations.
- Feature pages live under [ui/v2.5/src/components/](ui/v2.5/src/components/) (`Scenes`, `Performers`, `Groups`, `Galleries`, `Images`, `Tags`, `Studios`, `Settings`, `Setup`, `Tagger`, …). Shared widgets in `components/Shared/`.
- Internationalisation: `react-intl` with locale files under [ui/v2.5/src/locales/](ui/v2.5/src/locales/); messages are extracted with `npm run extract`. Translations are managed in Weblate — don't edit non-English locales by hand.
- Plugin UI surface: [ui/v2.5/src/pluginApi.tsx](ui/v2.5/src/pluginApi.tsx) plus the `patch.tsx` extension system.

## Conventions worth knowing

- **Movie === Group.** GraphQL still exposes `Movie*` types, but they map to `models.Group` (see [gqlgen.yml](gqlgen.yml)). New code should use the `Group` naming; "Movie" stays only as the public API alias.
- **Generated files are gitignored.** Re-run `make generate` (and `make pre-ui` if deps changed) after pulling — otherwise the backend won't compile.
- **Database changes require a numbered migration** in [pkg/sqlite/migrations/](pkg/sqlite/migrations/). Migration version numbers are strictly sequential; bumping one forces a database upgrade on next launch.
- **Filtering criteria are split across two places**: GraphQL input types in [graphql/schema/types/filters.graphql](graphql/schema/types/filters.graphql), and the SQL translation in [pkg/sqlite/criterion_handlers.go](pkg/sqlite/criterion_handlers.go). Adding a new filter usually touches both.
- **Dataloaders** ([internal/api/loaders/](internal/api/loaders/)) avoid N+1 queries inside GraphQL resolvers. When adding a new lookup, prefer adding a loader over fetching directly.
- **Plugins / scrapers ship as YAML/JS files**, not Go code — see [pkg/plugin/examples/](pkg/plugin/examples/) and `docs/` in the repo for the contracts.
- The contributing notes ([docs/CONTRIBUTING.md](docs/CONTRIBUTING.md)) emphasise minimalism: "features are easy to add and difficult to remove." Prefer extending an existing surface (plugin/scraper/hook) over adding a new core feature.

## Active UI refactor — design tokens, layout, gotchas

The frontend is partway through a Blueprint-dark → Apple/Notion-style modernization. Theme lives in [ui/v2.5/src/styles/_theme.scss](ui/v2.5/src/styles/_theme.scss) and [ui/v2.5/src/index.scss](ui/v2.5/src/index.scss); per-feature SCSS under [ui/v2.5/src/components/*/styles.scss](ui/v2.5/src/components/).

### Theme tokens — current state

- `$body-bg: #000` (pure black, user-set), `$card-bg: #242428`, `$textfield-bg: #2c2c30`, `$popover-bg: #2c2c30`, `$text-color: #f5f5f7`, `primary: #0091FF`, `$link-color: #0091FF`.
- **`$secondary` is now an iOS light gray (`rgba(#EBEBF5, 0.6)`).** Historically used as a dark surface bg across the codebase (popovers, dropdowns, dividers, react-select, clearable inputs, sidebar borders). **Never use `$secondary` for a dark surface** — use `$textfield-bg`, `$popover-bg`, or `rgba(white, 0.06–0.12)` instead. Most legacy `background-color: $secondary` rules have been migrated, but if you spot a white-looking surface, this is the first thing to check.
- Bootstrap-generated `.btn-secondary` is explicitly overridden to neutral white-alpha in [_theme.scss](ui/v2.5/src/styles/_theme.scss) (`rgba(white, 0.08)` → 0.14 → 0.18 on hover/active) — otherwise it would pick up the light `$secondary`.
- CSS custom properties on `:root` for radii (`--radius-sm/md/lg/pill`), shadows (`--shadow-sm/md/lg`), transitions (`--transition-fast/med`). Prefer these over hardcoded values in new component SCSS.

### Bootstrap integration

- Codebase pins **Bootstrap 4** (not 5). Variable overrides must be set **before** `@import "bootstrap/scss/bootstrap"` in [_theme.scss](ui/v2.5/src/styles/_theme.scss); CSS vars on `:root` go after.
- Bootstrap's `.bg-dark` utility uses `!important` — overrides require `!important` too (see `.top-nav.bg-dark` in [index.scss](ui/v2.5/src/index.scss)).
- Form-control inputs default to white bg in Bootstrap; the dark theme is wired via `$input-bg`, `$input-color`, `$input-border-color`, `$input-placeholder-color`, `$custom-select-*` overrides already in [_theme.scss](ui/v2.5/src/styles/_theme.scss). New form fields inherit automatically.
- React-Bootstrap `Navbar.Collapse` paints its own `bg-dark` layer on top of the navbar bg — neutralized to transparent at xl+ so the `backdrop-filter` blur works.
- SCSS expects deprecation warnings from Bootstrap 4 (Sass `if()`, `abs()` on percentages, etc.). Quick syntax check: `cd ui/v2.5 && npx sass --no-source-map --load-path=node_modules --quiet src/index.scss /tmp/out.css 2>&1 | grep -iE "^error"`.

### Layout & component gotchas

- **`.details-edit`** ([components/Shared/styles.scss](ui/v2.5/src/components/Shared/styles.scss)) is the shared action bar rendered by `DetailsEditNavbar` ([components/Shared/DetailsEditNavbar.tsx](ui/v2.5/src/components/Shared/DetailsEditNavbar.tsx)) — used across Performer/Studio/Tag/Group/Scene/Image/Gallery edit pages. Spacing is `column-gap`-based, **not** margin-based. The `customButtons` prop receives a fragment; if a child renders an empty `<div>` (e.g. `ImageInput` in non-edit mode, `<div><PerformerSubmitButton/></div>` when stash-box isn't configured), `> div:empty { display: none }` keeps the gap consistent.
- **`MainNavbar`** ([components/MainNavbar.tsx](ui/v2.5/src/components/MainNavbar.tsx)) — `LinkContainer` does **not** use `exact`, so `/performers/123` highlights `/performers`. Re-adding `exact` will lose active-nav indication on detail pages. Menu items are filtered by `configuration.interface.menuItems` (user preference) — don't replace the visible list with a single dropdown without preserving that.
- **Filter sidebar is currently disabled.** `useSidebarState` in [components/Shared/Sidebar.tsx](ui/v2.5/src/components/Shared/Sidebar.tsx) is a stub that always returns `showSidebar: false`. The JSX still exists in every list page (SceneList, PerformerList, etc.); section content doesn't mount because `SidebarSection` uses `mountOnEnter`. The `EditFilterDialog` is the only filter UI. To bring the sidebar back (planned: nav categories), restore the original `useSidebarState` body from git history and remove `.sidebar-toggle-button-container { display: none }` from [components/Shared/styles.scss](ui/v2.5/src/components/Shared/styles.scss).
- **FrontPage carousel arrows** are styled in [components/FrontPage/styles.scss](ui/v2.5/src/components/FrontPage/styles.scss) (`.slick-prev` / `.slick-next`), used by every `RecommendationRow`. The 40px chevron + edge-fade gradient overlays content because `padding: 0 40px` on `.slick-list` defines a "safe zone" — `overflow: hidden` clips at the **padding-box** edge, not the content-box edge, so cards rendered inside the padding region are still visible. Don't move the offset to `.recommendations-container` padding; that would leave the chevron area empty.
- **react-select** uses its own `.react-select__control`, `.react-select__menu`, `.react-select__multi-value` classes — independent of Bootstrap form-control. Both need styling. See the `react-select__control` block in [index.scss](ui/v2.5/src/index.scss).

### Edit-don't-redesign

The user prefers visual polish over UX restructures. Confirmed patterns:
- Keep navbar entity links visible — power-user hotkeys (`g s`, `g i`, ...) and the `menuItems` config rule out collapsing them behind a "Library" menu.
- Carousel safe-zone: content scrolls **behind** the chevron, not next to it. Cinematic, not utilitarian.
- "Modern minimalist" = Apple/Notion direction (airy spacing, larger radii, soft shadows, frosted-glass), not Linear/Vercel (dense, sharp, monochrome).
- The user edits `_theme.scss` tokens directly between sessions. Re-read the current values before assuming what's there.
